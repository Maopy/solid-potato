# 0.3.2 按礼物价值随机感谢

新增四档礼物感谢文案池，每档 8 条；价格未知时另有 6 条通用文案，共 38 条。末尾仍追加原配置中的随机 emoji。每个用户最后一次送礼后等待 5 秒，合并礼物名称后抽取一次文案，后续排队、填入和回执重试使用同一段文字。

## 启用

新包的抖音、视频号感谢配置已启用。旧配置需在已有 `rules.gift` 下合并以下字段，不要重复声明一个 `rules`：

```yaml
rules:
  gift:
    variation:
      enabled: true
```

`variation.enabled: false` 或不配置此项时，继续使用原来的 `template`。开启后正常感谢使用文案池，原来的 `overflow_template` 继续处理礼物名称合计超过 30 个字的情况。旧配置和数据不会被自动改写；停止旧进程，替换程序后重启，关闭旧直播页再重新打开。

## 分档方式

| 礼物单价范围 | 预设风格 | 条数 |
| --- | --- | --- |
| 0–99 | 简洁、自然地感谢 | 8 |
| 100–999 | 强调收到心意与支持 | 8 |
| 1000–9999 | 更明显地表达惊喜和感谢 | 8 |
| 10000 及以上 | 更郑重地感谢支持 | 8 |
| 价格未知 | 通用感谢，不推断价值 | 6 |

价格使用平台原始单位，两平台单独配置，不换算人民币。抖音从礼物结构的 diamondCount 字段提取，视频号从 reward_gift.price 提取。缺失、负数或超出支持范围的值按未知处理；字段明确为零时进入最低档。

同一感谢窗口取已知礼物中的最高单价，不乘数量、不累加连击金额。价格未知的礼物仍包含在感谢名单内；全部未知时使用通用池。这个版本不因价格高低丢弃礼物，也不改变感谢触发时间和发送频率。

抽取时优先避开同一用户上次使用的模板和该房间上一条生成的感谢模板。自定义文案池只有两条且约束冲突时优先避免该用户重复；只有一条时自然会重复。去重记忆限当前页面采集会话，重新连接或重启后重新开始，最多保留约一万用户。超长礼物名称仍遵循既有“感谢礼物飘屏”规则。

## 自定义

`config/gift-wording.example.yml` 列出全部 38 条预设，是配置片段，不能单独作为房间配置运行。可以将其中 `rules.gift.variation` 合并到房间 YAML，自行调整两平台的阈值和文案：

```yaml
rules:
  gift:
    variation:
      enabled: true
      unknown_templates:
        - '谢谢{nickname}送来的{gift_list}'
        - '感谢{nickname}，{gift_list}收到啦'
      tiers:
        - min_unit_value: 0
          templates:
            - '谢谢{nickname}的{gift_list}，收到啦'
            - '感谢{nickname}送来的{gift_list}'
        - min_unit_value: 1000
          templates:
            - '特别感谢{nickname}送来的{gift_list}，太惊喜啦'
            - '谢谢{nickname}的{gift_list}，这份支持收到啦'
```

模板只支持 `{nickname}` 和 `{gift_list}`；emoji 在渲染后自动追加，无需写占位符。阈值必须从 0 开始、严格递增，最多 16 档，每池 1–64 条非空且不重复的模板。省略 tiers 或 unknown_templates 时分别使用内置预设。更改配置需重启并重新打开页面。

## 验收与边界

只运行集成测试。验证视频号原生价格到感谢文案的完整流程、同一用户连续感谢不重复、回执丢失后保持原文案、抖音 protobuf 单价提取、YAML 分档边界与未知价格回退、最高单价选择、无效文案池预检，以及已有采集、发送和多任务隔离。没有向真实直播间发送测试消息。真实平台改变字段时可能回退通用池，不能根据缺失价格推断礼物为低价。

多任务入口和发送回显配置分别见 `docs/moderation-release-0.3.0.md`、`docs/moderation-release-0.3.1.md`。
