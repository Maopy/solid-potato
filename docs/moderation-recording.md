# 在场控中录制直播

抖音、视频号场控启动后即可使用录制，无需再启动 `wechat-capture` 或另一个代理。评论采集、感谢礼物、欢迎、关键词回复保持原有操作；启动场控不会自动开始录制。需安装 FFmpeg，默认从 PATH 查找 `ffmpeg`。

视频号保留原来的“录制直播”及下载任务面板，先进入并播放直播，再点击录制。在原下载列表暂停、继续、重试或移除任务。抖音直播页增加“录制直播”“下载任务”按钮，使用相同的点击录制、任务列表管理流程；有多条页面提供的流时可选择清晰度。只使用已登录页面提供或实际播放过的流地址，不能读取地址时提示先播放，不猜测下载地址。

仍按原来的方式启动 `run-wechat-auto.sh`、`run-douyin-auto.sh` 或 `run-controller.sh`，重新打开直播页加载脚本。多房间使用 controller，一个进程共用代理。不要同时启动旧的独立录制监听程序占用端口。

默认录制目录为系统“下载”文件夹下的 `直播录屏`（macOS 通常为 `~/Downloads/直播录屏`），独立于发布包，删除旧版本不会删除这里的录像。已有自定义目录仍按原配置使用。目录下按“平台 / 主播名”保存，同一主播各场录制放在同一目录，文件名统一为 `yyyy-mm-dd-hh-mm-ss-编号.mp4`（如 `2026-10-21-19-30-00-000.mp4`），避免并行录制时互相收尾。录制沿用已有 FFmpeg 引擎，先分段写入 TS，停止后转为 MP4。暂停、移除任务保留已有视频；退出场控会同时停止录制并等待文件收尾。不要强制杀进程，特别是在收尾期间。

可选配置如下，合并到实际启动使用的 YAML；示例文件不会单独生效：

```yaml
recording:
  enabled: true
  ffmpeg: ffmpeg
  segment_seconds: 1800
  output_dir: null # 默认系统下载文件夹/直播录屏
  # output_dir: /Volumes/Media/直播录屏
```

`output_dir: null` 或未设置使用系统下载目录；自定义目录建议填写绝对路径，相对路径仍以 YAML 所在目录为基准。统一入口修改 `config/unified.yml` 顶层的 `recording.output_dir`，controller 修改其自身配置；房间 YAML 的同名设置不覆盖统一入口。包含目录的 `ffmpeg` 路径以 YAML 所在目录为基准。`segment_seconds` 范围 1..86400，默认 1800。`enabled: false` 关闭录制集成入口。单房间用该房间配置；controller 使用自身顶层 `recording` 作为共享设置。TLS 诊断模式不接入录制。老 YAML 无需新增字段即可使用。

同一直播间同时只录制一份，重复任务会显示失败原因；可移除重复项，使用原任务暂停或继续。任务列表仅在本次运行内保留，重启场控后不会自动恢复旧录制或使用旧签名地址，应重新从页面点击开始。录制历史存入场控数据目录的 `recordings.sqlite3`，不会放进聊天审核数据库；删除任务不删除视频文件。最多保留 512 个本次任务，达到上限先移除旧项。

录制错误会按已有录制策略做有限重试，仍失败时在任务列表显示错误。流签名过期、切换房间或直播重开后，应重新打开当前房间并创建任务。录制不改变场控发送限速或未确认暂停状态。

升级只影响新启动的录制。旧版本目录中的已有视频不会自动搬迁，正在录制的文件不会改路径；删除旧版本前，需要先将这些视频移到外置目录。录制日志和任务数据库仍属于版本数据目录，实际媒体文件保存到配置的输出目录。

同一秒重启录制时延续该秒已有的最大分段编号，避免覆盖。主播昵称中的路径分隔符和不合法文件名字符替换为下划线；无法获得昵称时使用默认名称。不同同名主播在同一平台也会共用目录，但不会同时写入：主播目录已有录制时会提示占用，防止误处理仍在写入的分段。目录中的隐藏 `.recording.lock` 是进程占用锁，进程退出后内核自动释放，不需要手工删除。

## 默认最高画质（0.3.38 起）

两平台录制自动比较当前直播响应提供的画质档位，同档比较分辨率、码率，默认取最高可识别档位；没有额外配置项。抖音不再使用下拉列表的首项，视频号不再固定取默认 liveCdnUrl。只有当前源流时沿用该流，不猜测、改写 CDN 地址。录制始终直拷源流，无法提高主播原始推流的清晰度。
