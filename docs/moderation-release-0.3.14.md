# 0.3.14 定时文案的评论条数阈值

`timed_messages` 新增 `min_comments`，时间与评论条数两个条件同时满足后，才生成下一条定时文案。例如：

```yaml
timed_messages:
  enabled: true
  interval_seconds: 30
  min_comments: 5
  messages:
    - '欢迎新来的朋友，喜欢直播可以点个关注✨'
```

表示距离上一条定时文案至少 30 秒，而且期间收到至少 5 条新观众评论。评论先达到时等时间；时间先达到时等评论，条数满足后不用额外再等一轮时间。每次生成下一条定时文案后，时间与评论计数重新开始；忙碌或发送受限时仍沿用跳过本轮、不积压定时文案的机制，未消耗的评论计数保留。

`min_comments` 可取 0～10000，默认 0，保持旧版只按时间的行为。评论按房间和采集会话分别累计，不跨房间相加。只统计采集开启后的新评论，排除历史、重复消息和可识别的本机场控回复；关闭场控、暂停采集后清零，重新开启时重新累计。消息缺失或超出采集限额时可能少计，不会因无法确认的评论提前发送。

抖音使用已有网络评论事件，已安装的 0.3.13 抖音用户脚本也能配合新版后端计数，本次无需强制重装。视频号新增独立的评论活动计数，不依赖关键词功能是否开启、是否命中关键词。视频号启动新版后重新打开直播页加载新采集脚本。

请修改 unified.yml 实际引用的 douyin-auto.yml 或 wechat-auto.yml 中的 timed_messages。timed-messages.example.yml 仍是配置片段，需合并到房间配置，不会单独自动加载。

完整继承上一版配置，不改变已有文案、发送间隔或开关。示例文件在缺少 min_comments 时补充参数说明，现有值保持不变。正式 0.3.13 实例不会在打包时被重启；使用新版前先退出旧实例，等待录制收尾和代理恢复，再启动新版本。
