# 0.2.0 礼物感谢使用说明

本版支持抖音、微信桌面视频号直播页：按用户合并礼物，最后一次送礼后等待 5 秒，期间继续送礼则重新等待 5 秒。感谢只包含礼物名称，不包含数量；名称字符合计超过 30 时使用「感谢礼物飘屏」。生成后自动填入输入框，由你检查并手动发送。已有文字不会被覆盖，输入法组合输入期间不会填入。欢迎、粉丝团、升级、官方助手留待下一版。

## 安装与启动

发布包适用于 Apple Silicon Mac，需要系统中已有 `mitmdump`。解压后进入发布包目录运行命令。程序不包含你的 Cookie、证书私钥或历史日志。若已有可信证书和代理配置，可将配置中的 `storage.directory` 指向原来的场控数据目录，继续复用它。新目录会生成自己的代理证书。

两平台目前分开运行，先 Ctrl-C 停止一个，再启动另一个。不要同时运行两个代理。程序正常退出会停止代理；视频号模式会恢复原系统 HTTP/HTTPS 代理。日志包含采集到的用户来源标识及限定消息内容，仅保存在本机 `data/`。

## 抖音

1. 编辑 `config/douyin.yml` 中的 `room.url`，默认测试直播间为 `139244611014`。
2. 运行 `./run-douyin.sh`。
3. 使用已配置代理 `127.0.0.1:2024`、并信任终端所示本地 CA 的浏览器打开直播间，刷新页面。Firefox 使用自身证书库时需在该浏览器导入对应 CA；遇到安全警告先完成证书配置。
4. 保持聊天输入框空白、退出输入焦点，等待自然礼物。草稿出现后检查并手动发送；发送后再退出输入焦点，供下一条填入。
5. 用 Ctrl-C 停止。

## 视频号：首次选择感谢目标

视频号仍使用候选礼物识别，数量及当前主播身份未自动确认，因此必须明确选择感谢的礼物接收目标，尤其注意 PK 中其他主播。

1. 运行 `./live-archive-core moderation run --config config/wechat-observe.yml`。
2. 重新打开微信中的正在直播页面，点击绿色「场控诊断」→「开始采集」，等待自然礼物。
3. Ctrl-C 停止后，运行：

   ```sh
   ./live-archive-core moderation inspect-gift-targets --journal data/wechat/moderation-probe.sqlite3
   ```

4. 对照真实页面核对目标，把对应来源 ID 填入 `config/wechat.yml` 的 `candidate_preview.recipient_user_id`。不要仅根据 PK 列表顺序猜测。空值会在启动前拒绝，不会默认感谢所有目标。采样模式和正式模式必须使用同一个数据目录；若改了目录，相应调整上面的日志路径。

## 视频号：使用自动填入

1. 运行 `./run-wechat.sh`，按需允许系统代理及本地证书设置。
2. 重新打开正在直播的页面，点击「场控诊断」→「开始采集」。
3. 点击「聊一聊」展开空输入框，保持编辑区展开。微信失焦会收起输入框，因此本版允许填入聚焦的空输入框；已有文字及输入法组合输入仍受到保护。
4. 目标主播收到自然礼物后，等待该用户最后一次送礼后 5 秒。查看感谢草稿，检查后手动点击评论发送。程序不会点击评论或按发送键。
5. 「暂停采集」可停止生成和填入；Ctrl-C 停止程序并恢复代理。不要在准备停止时继续发送。

## 本版限制及验收

草稿队列有上限，生成后等待输入框最长约 20 秒，超时会丢弃，不保证每个礼物都能填入。刷新、重连、暂停期间不保证补采；同 ID 重复及修订已处理，新 ID 的连击尾条仍可能生成额外感谢窗口，已列入下一版待办。视频号目前限定已观察到的桌面原生礼物消息结构，不保证所有客户端与礼物类型覆盖。

本版已通过模拟平台消息→注入 SDK→本地 HTTP→日志→输入框的集成验收。真实微信页面另已确认固定测试文案能填入，评论按钮变为可用，随后清空草稿，全程没有发送。此次真实固定文案验收不等于已覆盖所有自然礼物类型。抖音名称感谢通过完整本地集成链路；本次未重新验收真实抖音自然礼物。

进一步开发记录见 `docs/moderation-next-version.md`。
