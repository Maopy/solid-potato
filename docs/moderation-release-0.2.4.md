# 0.2.4 感谢文案与随机 emoji 配置

抖音和视频号现在共用 `rules.gift` 的感谢文案配置。视频号也会使用自定义 `template`、`overflow_template`，保持不带数量感谢的事件语义。每条生成的感谢在末尾追加一个随机候选表情，默认池为 🎁🎉💖✨🌟💐。

```yaml
rules:
  gift:
    enabled: true
    show_quantity: false
    template: '感谢{nickname}送来的{gift_list}'
    overflow_template: '感谢礼物飘屏'
    emojis: ['🎁', '🎉', '💖', '✨', '🌟', '💐']
```

普通模板支持 `{nickname}`（观众昵称）与 `{gift_list}`（合并后的礼物名称列表）；飘屏模板支持 `{nickname}`。例如改为 `template: '谢谢{nickname}赠送的{gift_list}'`，可能生成 `谢谢小明赠送的玫瑰、爱心💖`。花括号字面量使用 `{{` 和 `}}`。

`emojis` 省略时，YAML 默认使用上述六个候选；设为 `[]` 关闭追加。每个列表项是一个完整尾缀，支持 `👩‍💻` 等组合表情，不按 Unicode 字符拆开。最多 32 项，每项非空、最多 16 个 Unicode 字符、不含控制字符。随机选择允许相邻感谢出现相同表情。

表情在草稿生成时只选择一次，草稿日志、队列、输入和提交都使用同一份完整文本。回执重试、重复命令不会重新随机。普通感谢和飘屏感谢均追加，欢迎/升级及固定测试文案不追加。

长度预算包含表情。普通文案加表情超过 `limits.max_text_chars` 时使用配置的飘屏文案并追加同一个表情；若仍超长，跳过这条感谢，不截断组合表情，不取消其他用户排队的感谢。礼物名称超过 30 字的原飘屏规则保持不变。

## 更新

Ctrl-C 停止原程序，用新包的 `live-archive-core` 替换旧程序，保留 `config/` 和 `data/`。可在原 YAML 中编辑上述字段；仅更换程序、没有填写 `emojis` 时也会启用默认池。重新启动并刷新直播页面加载新配置。

自动发送仍由 `sending.automatic` 控制，模板设置不会自行开启自动发送。其余使用步骤见 [自动发送](moderation-release-0.2.1.md)及[视频号自动展开输入框](moderation-release-0.2.3.md)。本次只运行本地集成测试，没有向真实直播间发送测试消息。

核心离线重放以及旧 `moderation probe` 参数入口维持原有确定性默认行为；本版默认随机池应用于 YAML 配置入口。
