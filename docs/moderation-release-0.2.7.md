# 0.2.7 视频号长用户标识与原始日志转发修复

真实采集中，“别**”的爱心和“陌**”的玫瑰、棒棒糖、爱心均已收到原生 20009 礼物消息，收礼目标与配置一致，但这两个账号的用户标识长度为 148 字符。此前采集端和控制端按最多 128 字符验证，将它们当作无效标识跳过，因此没有生成感谢。

本版将视频号用户标识上限调整为 256 字符，保留完整标识，不截断、不合并不同账号。同步覆盖采集、桥接协议、感谢候选与日志分析。消息 ID、礼物 ID、昵称等原有限制继续生效；控制字符与超长标识仍拒绝。礼物按用户等待最后一次送礼后 5 秒、合并名称和原有收礼目标过滤不变。

同时修复同源代理没有将 `/raw` 列入允许转发路径的问题。此前原始采集虽开启，上传会返回 403，数据只留在页面内存，原始日志表为空。现已允许同源、认证后的原始日志请求转发到本机桥接服务，并补充通过实际代理请求处理函数和本机 TCP 桥接的集成测试。来源、请求体大小和认证约束保留。

本次排查中，已修复正在运行的代理脚本，页面缓存的原始消息成功补入本地数据库，用于确认真实原因。这个临时修复不能替代升级：旧二进制重新启动时会重新生成旧代理脚本。新版包含正式修复。

## 更新

Ctrl-C 停止旧程序，用本包 `live-archive-core` 替换旧二进制，保留 `config/` 和 `data/`。重新启动，关闭并重新打开直播页面加载新脚本，再点击“开始采集”。不需要修改感谢或清理配置。

更新后观察“原始采集”的待入库分片数能够消退、没有持续 `bridge_http_403`；长用户标识的后续新礼物应进入候选和感谢流程。之前跳过的礼物不会被补发感谢，也不会从原始历史日志重新发送。

集成测试使用两个前 147 字符相同、最后一位不同的匿名 148 字符标识，验证两个账号分别产生感谢、填入和模拟提交，避免截断导致账号合并。测试还覆盖同源代理路径、来源拒绝、重复确认和本地持久化。本次没有向真实直播间发送固定测试文案或回放历史礼物。
