# 0.3.15 视频号序号为 0 的评论回显确认

修复视频号感谢礼物、定时文案偶发停止的问题：某次本地发送结果不明确时，程序暂停后续发送；即使评论随后出现在服务端轮询里，序号为 0 且轮询开始于点击之前的回显仍会被排除，导致后续感谢不断过期。

现在仅在本机已经发起的那个 UI 点击所产生的原生请求中，观察成功返回的 server_msg_id_str，并将它绑定到该条待确认发送。随后必须在原有的服务端评论轮询里看到同一个消息 ID、相同发送人和文案，并有独立的 local_client_msg_id，才确认回显并解除对应暂停。不增加平台请求，不重试发送，不把发送接口成功或同文案历史消息单独当作回显。回显先于发送响应到达时，最多暂存 4 条候选，等待消息 ID 精确匹配。

保留旧的有效序号确认路径、发送者校验和持久化确认机制。错误响应、不同消息 ID、不同发送者、缺少本地关联、历史消息都不能借此放行。仍无法确认时继续暂停，避免刷屏和重复感谢。

配置完整继承当前运行的 0.3.14。保留 min_comments 等现有设置，定时文案仍需同时满足时间和评论数条件。

使用新版前先在旧终端 Ctrl-C 正常退出，等待录制收尾和代理恢复，再启动新版本。视频号必须关闭旧直播页、重新进入并选择任务，加载新的页面采集脚本；已过期的感谢不会补发，已发送的定时文案不会重发。抖音无需为本次视频号修复强制重装用户脚本。

验证包括序号 0 的跨点击长轮询、精确消息 ID 匹配、回显与响应乱序、错误身份与历史消息排除，以及重复命令/丢失 ACK 下不重复点击、持久化回显后恢复后续队列的完整模拟集成测试。验证不向真实直播间发送测试评论。
