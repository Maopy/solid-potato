# 中控实时内容首版

统一中控的“直播间”页按已配置的直播间或动态接入的抖音直播间展示内容。默认同屏展示两个直播间，也可切换为单直播间。每个窗口顶部独立选择直播间，主播语音与公屏文字在同一条时间线上按时间混排，以浅绿色语音卡片区分。语音卡片以与观众昵称相似的“主播 + 语音图标”开头，与正文同行，时间栏显示说完的时间，不显示时间范围或重复标签。视频号沿用既有任务与页面的绑定方式。

- 直播间选择框优先显示从当前直播资料读取的主播昵称；抖音与视频号均自动更新。同名主播用平台与序号区分，昵称未就绪时显示等待提示，不显示长房间 ID。
- 默认跟随最新内容；向上滚动、搜索、时间筛选或点选内容后进入回看。回看时画面保持稳定，新到内容通过底部计数提示，点击“回到实时”清除关键词和时间范围并回到最新。
- 桌面双间模式并排显示两个直播间，窄屏上下排列。选择已在另一窗口展示的直播间会交换两窗位置，避免重复展示。
- 两个窗口各自更新、搜索、滚动和回看，暂停其中一个不会暂停另一个。各直播间分别保留当前页面内的筛选、阅读位置和选择。点击语音或留言，高亮时间区间重叠的内容，只表示时间关系。
- 同一秒的内容共用一个时间标记；只有留言的时段超过三条可展开，包含语音的时段保持完整时间顺序。搜索支持文字与用户名称，也可独立隐藏语音或留言。
- 语音可从中控开启或关闭：开启请求交给已连接的直播页获取音频，支持取消、超时和错误反馈。直播页的语音开关继续可用。

时间线每个直播间保留最近 30 分钟的记录，以留言时间和语音说完时间计算，不再设置 2000 条上限。写入和读取时自动清理过期内容；中控轮询时也会移除回看画面中的过期记录，并尽量保持阅读位置。刷新中控、停止识别或页面断开不影响仍在 30 分钟窗口内的内容；重启后台后清空。从 0.5.6 起，新生成的语音转写同时保存到各直播间日志数据库的 speech_transcripts 表，记录运行及连接标识、片段开始和结束时间与文本；不保存音频。历史未持久化的转写无法恢复。公屏观察日志仍沿用原有审计规则。

抖音优先使用原生消息时间，视频号使用接收时间。主播语音使用 FunASR FSMN-VAD 按停顿分段，按片段结束时间显示；播放缓冲和模型处理会带来延迟。为避免背景音乐误滤主播发言，不再使用声纹筛选；语音与歌词无法可靠分离，可能显示歌词。持续音频最多每 8 秒分段。分段音频按顺序进入有界识别队列。

中控模式下，直播页连接后自动采集公屏，与场控开关独立；关闭场控只停止自动回复等动作，公屏继续更新。关闭期间的留言只用于展示，重新开启场控不会补发这些留言的自动回复。公屏覆盖仍取决于现有采集器。视频号首次成功轮询只建立历史水位，之后采集新文字；中控展示不要求开启关键词回复或定时文案。网络来源的重复留言按用户与原生消息 ID 去重。

验证：`cargo test -p live-archive-core --lib moderation::timeline`，以及 `cargo test -p live-archive-core --test moderation_dashboard --test moderation_speech_integration --test moderation_userscript_integration`。前端执行 `node --test tests/moderation*.test.cjs`；浏览器测试需要 Playwright，可用 `PLAYWRIGHT_MODULE` 指向本地安装，`PLAYWRIGHT_CHANNEL` 选择已安装浏览器（默认 `msedge`）。`DASHBOARD_SCREENSHOT` 可指定示例数据截图输出路径。
