# 0.3.12 异常退出后的启动锁恢复

修复启动时仅凭 PID 文件存在就拒绝运行的问题。旧进程异常退出后，moderation-probe.lock 可能残留，旧版会报 another probe owns this directory。

现在先获取操作系统管理的目录独占锁，再核实旧 PID：在 macOS、Linux 上，确认旧进程已退出时自动清理其 PID 文件并继续启动；进程仍运行、无权核实或锁文件无法识别时保留现有锁并说明原因，不终止任何现有实例。正常退出清理 PID 文件。moderation-probe.guard 是稳定的锁载体，会保留为空文件，独占状态由操作系统随进程退出自动释放；不要手动删除正在运行实例的 guard 文件。

保留统一启动入口、场控开关及双平台录制。双击启动场控.command，同时启动两个平台。完整继承上一版 config，不改文案和开关。

已有实例正常运行时无需再次启动。换版本前在原启动终端按 Ctrl-C，等待录制收尾和代理恢复，再运行新版。仍在占用的代理端口不会被强行抢占。验证包括旧 PID 已退出、当前 PID 仍运行、同时申请同一目录、强制终止持锁子进程后恢复，以及实际代理启动退出回归。没有停止或改动用户当前运行的实例。
