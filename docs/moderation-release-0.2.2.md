# 0.2.2 评论控件定位修复

针对视频号第一次填入后出现 `submission_unconfirmed`、后续草稿被 `submission_unknown_restart_required` 拦截的问题，修复发送控件选取中的一个缺陷：文本同为「评论」的外层容器可能包住实际按钮，旧版优先点击外层，跳过了子按钮自己的提交处理器。

现在优先定位实际 BUTTON，其次具有 button 角色的控件；自定义控件选择最内层文本标签，使点击事件经过提交处理器。多个独立控件仍会拒绝发送，禁用祖先也会阻止点击。未知提交结果继续停止自动发送，不自动重发。诊断「本地发送控件」增加选中元素标签，帮助实页核对。

## 更新

先 Ctrl-C 停止原来的场控程序。可将新包中的 `live-archive-core` 替换到原包目录，保留你已经修改的 `config/` 和 `data/`，继续复用感谢目标、代理证书和原启动命令。不要用空目标示例覆盖自己的配置。

重新打开或刷新直播页，加载新脚本；只替换程序不会更新旧页面里已注入的脚本。若输入框仍有旧草稿，先人工处理，再展开空输入框并开始采集。旧页面中未知结果的停止状态不会自动解除。

自动发送的配置和使用步骤见 [0.2.1 使用说明](moderation-release-0.2.1.md)。`sending.automatic: true` 启用，旧手动配置保持不发送；固定文案测试仍不能开启发送。

## 验证与边界

集成测试增加相同文字的外层容器、嵌套实际按钮，以及自定义标签冒泡提交，检查连续两次感谢、重复命令和回执重试不会重复点击。既有人工草稿、禁用或多个控件、人工修改、暂停和未知结果保护继续验证。只运行集成测试。

用户本地日志确认第一次动作结果未知，后续四条草稿被保护性拦截；这些日志没有证明实际点击的是哪个 DOM 元素。嵌套容器缺陷由代码检查和集成复现确认，真实页面是否还有其他问题仍需复测。本轮真实微信页面验收被「For account security, log in again」登录提示中断，未点击发送，没有发送测试消息。

新 ID 连击尾条等已知礼物识别问题仍保留到下一版本。
