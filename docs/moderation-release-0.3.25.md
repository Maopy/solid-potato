# 0.3.25 抖音刷新交接、草稿恢复与录制修复

## 页面刷新

离开页面时先释放旧连接，再清理早期网络钩子；跨房间导航也允许旧连接的 goodbye 完成。新版后台通过同标签页标识和有效的一次性房间票据交接连接，撤销旧绑定并丢弃旧待发草稿，不补发旧消息，也不允许其他标签页夺取自动发送连接。

新脚本兼容旧后台：刷新撞到旧连接尚未释放时，以同票据有限重试，保持“连接中”，不再立即停止并显示异常。票据、房间或身份错误仍拒绝。

## 输入草稿

抖音自动发送时暂存文本草稿、选区与光标，填入场控文案并沿用通用发送流程，随后恢复原草稿。发送被拒绝时也恢复。期间若有新的按键、粘贴或 beforeinput，会先恢复原稿，取消本次自动点击，让新输入继续作用于原稿。重复命令不再次替换草稿。

输入法组词以及带图片、视频或 @提及等尚不支持完整快照的富文本草稿继续等待，避免破坏用户内容。仅填入模式继续保护原有草稿，不主动替换。长文案仍由抖音自动截断，不自行裁剪、不添加省略号、不等待发送确认或自动补发。

## 礼物与定时文案

截图中的鲜花、粉丝团灯牌、小心心已被识别并生成感谢；旧发送逻辑因输入条件不满足使文案等待 20 秒后过期。本版文本草稿暂存消除了普通输入占用导致的长期阻塞，并记录 input_wait_changed，明确输入框、后台页面等等待原因。

min_comments 计数不再到阈值封顶，显示本页累计有效评论和自动回复排除数，保留完整按原因排除统计。仍排除自动回复、重复消息和历史/无效评论；当前轮在生成定时文案后重计。时间与评论数均满足但暂时不可发送时，保留已满足的条件，可发送后立即排队，不再额外等完整 interval_seconds，不积攒多条定时消息。

## 录制

录制复用 document-start 捕获的当前房间 fetch/XHR 信息，包括配对前已返回的直播流。播放器只有 blob 地址、src 为空或资源计时缓冲被清空时，仍可从房间信息及增量媒体资源缓存获取地址。维持“录制直播 / 下载任务”操作，不自动启动录制。

配置完整继承当前运行版本。用户脚本更新并刷新即可启用前端修复；计数统计和同标签页即时接替需在现有录像结束后使用本版后台启动入口。当前运行录像无需中断，权限范围不变。
