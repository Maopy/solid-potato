# 下一版本待办

当前范围：抖音、视频号不带数量感谢礼物，支持自动填入、手动发送和显式开启的自动发送。0.3.0 已增加共享代理、多直播间任务隔离与账号预算；0.3.1 已改进礼物采集并区分本地提交、网络回显和未确认。进场欢迎已加入 30 秒合并，详见 [进场用户合并欢迎](moderation-welcome.md)；粉丝团、升级、官方助手和其他产品 UI 继续延后。

## 礼物尾条可能造成多余感谢窗口

已知风险：平台可能在送礼结束后用新的 20009 消息 ID 推送总结/结算消息；目前无法可靠判断它是新礼物还是上一轮尾条，因此可能多生成一次感谢。相同 ID 的重复与修订已独立处理；0.3.1 明确续送增长会延后 5 秒，20013 展示消息独立留存、不触发感谢。不显示数量不能消除这一语义问题，不能按数量相同或 combo=0 直接删除事件。

下版应使用明确的连击组/阶段/结束标记与真实样本核对。按文档、发送者、礼物、接收目标隔离，保留修订和来源关系；先做匿名真实样本回放，再做自然事件集成验收。当前测试并未确认存在真实重复感谢，只是该情况尚未排除。

## 后续功能与问题

- 视频号已识别的明确进场通知走合并欢迎候选；其他 10005 仍仅诊断。粉丝团加入、等级升级继续确认事件语义、用户身份字段和房间归属。
- 当前主播/房间自动确认、PK 目标选择体验、跨房间绑定撤销。
- 礼物数量与连击尾条解析、漏采/重连补采、更多客户端/编辑器适配。
- 真实客户端的网络回显现场复验、发送账号自动识别与官方送达回执；0.3.1 当前只记录网络回显证据，不宣称所有观众可见。
- 更多队列控制、超过等待期限的草稿处理及诊断简化；本版空闲输入保护、暂停取消和有限队列仍保留。
