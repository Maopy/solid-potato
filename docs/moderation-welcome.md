# 进场用户合并欢迎

抖音和桌面视频号按直播间、页面会话独立收集进场用户。第一位用户进场后等待 30 秒，将这段时间内的用户合并为一条，例如「欢迎甲、乙、丙来到直播间」。后续进场不会延后当前窗口；没有新用户时不生成消息。一个用户 60 秒内重复进场不会重复欢迎。

名单按进场顺序排列，昵称最多显示 12 字。超过配置的消息长度时缩短名单，例如「欢迎甲、乙等100位朋友来到直播间」，仍只生成一条。欢迎沿用 `rules.welcome.template`，其中 `{nickname}` 现在替换为合并后的名单。`rules.welcome.enabled: false` 可以关闭欢迎。

```yaml
rules:
  welcome:
    enabled: true
    template: '欢迎{nickname}来到直播间'
```

礼物感谢、等级升级优先于进场欢迎。抖音会从尚未发送的欢迎名单中移除已触发礼物或升级互动的用户；视频号会从尚在收集的名单中移除送礼用户。欢迎生成后有效期为 10 秒，30 秒收集时间不占用有效期；预算或输入框占用导致过期时丢弃。暂停采集、页面退出或直播结束会清空未完成名单。

抖音使用已有的原生 `member.entered` 事件。视频号识别原生 `msg_list.type=10005` 中带稳定用户 ID、消息 ID 和昵称的通知，且通知内容必须严格为「来了」「昵称 来了」或「昵称来了」。支持普通文本和现有 JSON/Base64 JSON 内容；嵌套联系人与外层用户身份冲突、内容为空或不匹配时忽略。普通聊天（type=1）、仅以“来了”结尾的任意文字、未知消息类型均不触发欢迎。

视频号仍作为绑定页面内的 `member.candidate` 处理，保留 `confidence=candidate`、`room_verified=false`，不把它伪装成已验证的房间事件。沿用现有 `candidate_preview` 的已选目标和页面会话，启用视频号欢迎需要启用该配置；页面切换仍使用现有任务停止机制。已加入合成 SDK、HTTP、30 秒计时和填入测试，实际直播中的通知字段仍需现场验收，未匹配的通知继续作为诊断。

发布配置 `release/douyin.yml`、`release/wechat.yml` 及其自动发送、多直播间配置已打开欢迎。发送行为沿用原有模式：默认填入后手动发送；已开启 `sending.automatic: true` 的运行可自动发送，并继续遵守发送间隔和账号预算。粉丝团加入的欢迎仍使用原有独立规则。

## 超粉、星守护身份欢迎

带有这两类身份的用户进场时生成独立欢迎，例如「欢迎超粉甲来到直播间，感谢支持！」或「欢迎星守护乙来到直播间，感谢支持！」。这是进场欢迎，不根据开通、升级或普通聊天触发。

节流按直播间、页面会话和稳定用户 ID 隔离：从生成独立欢迎起，同一用户 60 秒内不再生成身份欢迎；更换消息 ID、昵称或从超粉变为星守护均不能绕过。其他用户不共享这份冷却。身份用户从尚未发送的普通欢迎名单中移除，60 秒内的后续普通进场也不会再进入 30 秒名单。已有发送间隔、输入框保护、账号预算和 10 秒有效期继续生效。

```yaml
rules:
  supporter_welcome:
    enabled: true
    template: '欢迎{title}{nickname}来到直播间，感谢支持！'
```

`{title}` 为“超粉”或“星守护”，`{nickname}` 为单人昵称。开关独立于普通 `rules.welcome`；关闭身份欢迎后，符合条件的进场用户仍按普通欢迎规则处理。

视频号在原有明确的原生进场通知中读取 `finder_live_contact.badge_infos[].badge_name`，仅接受完整的“超粉”“星守护”。同一用户同时携带两种徽章时采用“星守护”称呼，共用同一份冷却。昵称或普通消息中出现这些词不会建立身份，未知徽章保持普通欢迎。真实直播的徽章字段仍需现场验收。

统一核心和抖音在线归一化已支持 `SupporterEntered` / `supporter_title`，但当前抖音原生解码器没有经过确认的对应身份字段，所以不会猜测粉丝团等级、消费等级或图标来触发这两类专属欢迎。抖音的普通进场欢迎继续工作；抖音身份识别接入仍需真实消息样本。

## 看不到欢迎时的检查

实际启动的自动配置中必须有 `rules.welcome.enabled: true`。本地打包继承旧配置，因此旧配置中关闭的开关也会保留。修改 YAML 后需重启后台加载，再开启场控，单独刷新页面不会重新读取配置。

0.3.26 修复当前抖音原生进场缺少公共事件时间的问题：仅对已核对房间的原生 action=1 进场通知，用所在 WebSocket Response 的服务器时间进行实时性检查；过期帧及显式旧时间仍拒绝。旧版即使打开欢迎，也可能因 `live_eligible=false` 跳过进场。
