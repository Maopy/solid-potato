# 0.2.3 视频号收起输入框时自动准备感谢

自动发送模式收到待处理感谢后，自动点击真实页面的「聊一聊」入口，展开编辑器，再使用原来的填入、文本复核和评论提交链路。不需要用户一直展开输入框；用户收起后，下一条待发送感谢会重新准备编辑器。仅有队列待处理时才展开，暂停、停止、页面隐藏、输入法组合输入、结果未知或输入框已有文字时仍受原保护。

入口必须唯一、可见、可用，匹配实际页面的圆角聊天入口；标题虽然同名，但不会被点击。初次定位错误排除了有两个子元素的真实入口，本版已按实页核对修正。自定义评论控件继续选择内部标签，通过事件冒泡触发实际处理器。

配置仍使用 `sending.automatic: true`。旧手动填入配置保持原行为；固定 `fill_test_text` 模式会测试展开和填入，始终禁止发送，并给予两分钟准备时间。自然礼物草稿仍保留原约 20 秒等待期限和发送预算。

## 更新

Ctrl-C 停止旧程序，再用新包的 `live-archive-core` 替换旧目录中的程序，保留已修改的 `config/` 和 `data/`。重新打开或刷新直播页面，点击「开始采集」即可，输入框可以收起。其他设置见 [自动发送说明](moderation-release-0.2.1.md)。

同日，自然礼物实页验收已看到当前账号连续两条感谢出现在公屏，分别为小星星和墨镜；整个验收阶段输入框起初收起，两轮之间没有人工展开，诊断确认 `input_opened` / `input_submitted`。测试期间没有发送固定测试文案，没有操作赠送礼物。新 ID 尾条、数量等原识别边界保持不变。
