# 自动点赞

点赞由页面的独立开关控制，与场控和录制开关互不影响。每次重新加载页面都默认关闭，点击“开启自动点赞”后才操作。

在房间配置的顶层设置 `likes`，完整示例见 `config/likes.example.yml`。统一入口使用 `douyin-auto.yml` 和 `wechat-auto.yml`。已有配置会保留，打包时仅为尚无 likes 配置的自动场控文件补充默认方案。

| 字段 | 作用 |
| --- | --- |
| enabled | 是否提供点赞功能与开关，默认 false |
| mode | continuous 持续；clock 自然整点批量 |
| interval_ms | 视频号点击间隔，100–60000 毫秒，默认 800；抖音使用独立的 33 毫秒键盘连发节奏 |
| every_minutes | clock 的分钟周期，必须整除 60，默认 10 |
| batch_count | clock 每批操作次数，1–10000，默认 200 |
| missed | catch_up_once 恢复时最多补一批；skip 跳过错过的整点（允许 3 秒调度误差） |
| target_selector | 可选 CSS 选择器，需唯一匹配可见控件；留空时自动识别或手动定位 |

抖音默认 clock：按电脑本地时间在每小时 00、10、20、30、40、50 分启动一批 200 次。开启时由后台检查当前自然时段；未触发则立即补一批，已触发则等待下一时段。后台按标签页和直播间持久记录触发状态，同一运行目录下刷新或重启不重复触发。抖音持续按住原页面 Z 快捷键，后续每 33 毫秒发送 repeat=true 的 keydown，模拟按住键盘时的自动连发，批次结束或关闭时才发送 keyup，无需定位按钮；评论框、文本编辑区域或嵌入页面获得焦点时暂停，避免输入 Z。抖音不再使用鼠标点击间隔；200 次键盘事件约 6.6 秒完成一批（浏览器调度可能延长）。页面隐藏、窗口失焦或焦点进入编辑框时立即松开 Z，恢复后重新按住；回到页面后不会把所有错过的批次集中补完。如果正在完成旧批次，最多再保留一批。

视频号默认 continuous：每 800 毫秒操作一次。页面隐藏时暂停，恢复后继续正常间隔，不集中补点。

视频号自动识别直播画面右下角的原生点赞控件，无需手动定位。控件不唯一、不可见或已被遮挡时暂停点击。两平台在文本输入框获得焦点时暂停点赞，移开焦点后继续，保留草稿和光标。单任务自动绑定，不显示选择面板。

切换直播间、页面连接停止或发生点击异常时停止点赞。没有找到唯一可见的目标时不点击，保留等待状态。面板“已操作”表示向原页面发出的手势次数，不代表平台确认的点赞数；登录状态、风控和平台频率限制仍由原页面处理。

本次验证使用模拟事件与调度时钟，没有在真实直播间执行点赞或发送评论。
