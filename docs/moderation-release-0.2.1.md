# 0.2.1 自动发送礼物感谢

抖音和微信桌面视频号新增可选自动发送，沿用按用户等待最后一次礼物后 5 秒、合并礼物名称、不显示数量的感谢规则。旧配置继续自动填入、手动发送；默认不启用自动发送。

## 启用

解压 0.2.1 包后，使用 `config/douyin-auto.yml` 或 `config/wechat-auto.yml`。抖音修改直播间 URL；视频号必须先按 [原使用说明](moderation-release-0.2.0.md)核对并填写 `candidate_preview.recipient_user_id`，不能留空。`wechat-auto.yml` 和 `wechat.yml` 是独立文件，目标需填在实际运行的配置中。两平台仍分别运行。

```sh
# 抖音
./run-douyin-auto.sh

# 视频号
./run-wechat-auto.sh
```

也可以在原本有效的填入模式 YAML 中添加：

```yaml
sending:
  automatic: true
```

设为 `false` 或删除这一段，停止并重新启动后恢复手动发送。配置不能热切换。`observe`、规则预览、TLS 诊断，以及包含 `fill_test_text` 的固定测试配置均拒绝开启自动发送；真实页面测试仍使用固定测试模式，只填入，不发送。

## 实际行为

- 抖音在当前输入框同一容器内定位「发送」，视频号在输入框附近容器定位「评论」；仅操作唯一、可见且可用的本地控件。找不到或有多个控件时拒绝发送，不猜测、不调用平台接口、不模拟 Enter。
- 输入框已有文字、输入法组合输入、页面隐藏、暂停采集、房间或文档绑定变化时不会提交。填入后再次核对文本和控件，人工修改的内容不会被发送。拒绝发送后草稿可能仍留在输入框，需要手动处理。
- 视频号先点击「开始采集」并展开「聊一聊」。抖音保持输入框空白且不聚焦。诊断面板会显示填入/提交结果；`input_submitted` 只表示点击后编辑器清空，不能证明平台已送达。
- 每条命令在当前文档最多执行一次；重复命令和回执网络重试不会重复点击。点击异常、输入框未在检查窗口内清空或回执长期缺失会标记为未知并阻止后续自动发送，需人工核对后停止、重新启动。不会自动补发未知结果。
- 发送尝试共用该文档的间隔和分钟预算，默认至少 8 秒一次、每分钟最多 6 次；使用 `scheduler.min_interval_ms` / `account_per_minute` 调整，范围仍为 8–60 秒及 1–6 次。等待发送期间草稿仍可能过期，队列有上限，不保证全部发送。
- 自动模式仅允许同一服务内一个活动页面配对，避免多个标签同时提交；不要另开第二个场控进程。账号和视频号当前主播身份仍未自动核实。

## 验收与后续

自动发送通过本地模拟页面的完整集成链路：礼物解码/候选识别→按用户合并→队列→填入→按钮提交→回执→SQLite。覆盖丢失回执、重复命令、发送间隔、已有人工草稿、禁用/多个评论控件、填入后人工修改、暂停、未知结果停止。没有运行单元测试，没有在真实直播间发送任何测试消息。

本轮真实微信窗口切换且窗口定位超时，未完成新发送控件的真实页面验收；实际页面结构不符合定位条件时会拒绝发送，需要据诊断适配。0.2.0 的真实固定文案填入验收仍有效。

新 ID 连击尾条可能多生成感谢的旧问题继续留到下一版；自动发送也可能发送这些额外感谢，不带数量不能消除这个问题。自动模式不会修复这一识别问题。礼物数量、欢迎、升级等仍不纳入本版。
