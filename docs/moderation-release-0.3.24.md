# 0.3.24 抖音发送等待、评论计数与录制修复

## 礼物感谢

鲜花、粉丝团灯牌、小心心等已正确识别，但感谢可能因输入条件连续不满足而在 20 秒后过期。本版修正空输入框长期保留焦点时被一直判为忙碌的问题：只要内容为空、未输入法组词，并且 3 秒内没有输入活动，就可发送。正在编辑、有草稿或页面在后台时仍阻止发送。记录 input_wait_changed 原因变化，便于定位；不重发、不补发旧感谢、不等待回显。

## 定时文案

有效评论计数不再到 min_comments 阈值就封顶，新增本页累计计数与按原因排除统计。仍排除自动回复、重复消息、无效或历史评论。当前轮在生成文案后重新计数，不把采集总数混作本轮有效评论。

时间与条数均满足但输入框暂忙时，保留条件，恢复可发送后立即交给统一队列，不再重新等待完整 interval_seconds。保持发送预算及礼物优先，不积攒多条定时文案。

## 抖音录制

录制现在复用 document-start 捕获的同房间 fetch/XHR 进场信息，包括场控配对前已经返回的直播流。播放器使用 blob 或清空资源记录时仍可从房间信息定位地址。增量缓存已加载媒体资源，不再只依赖点击时的 performance 快照。保持“录制直播 / 下载任务”的交互，不自动发起录制或测试弹幕。

配置完整继承上一版本。用户脚本需更新并刷新抖音直播页；计数统计和等待时机涉及 Rust 后台，需在录像结束后使用本版启动入口。更新脚本可继续兼容旧后台，不需要为了前端修复中断现有录像。权限范围不变。
